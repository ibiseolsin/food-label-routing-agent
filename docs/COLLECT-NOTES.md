## m05 파싱 규칙을 옮기며 고친 것 둘

`m05-rag-chatbot-service/app/scripts/fetch-corpus.mjs` 의 규칙을 Python 으로 옮겼다.
언어를 옮기는 과정에서 **조용히 틀리는** 자리가 둘 있었고, 둘 다 실측으로 잡았다.

### 1. `\b` 는 언어를 건너오지 않는다

고시 원문은 호 마커가 앞 단어에 붙어서 온다 — 「…표시ㆍ광고2. 건강기능식품…」.
JS 의 `\b` 는 ASCII 기준이라 한글과 숫자 사이가 단어 경계지만, Python 의 `\b` 는 유니코드
기준이라 「광고2」 가 한 단어다. 그대로 옮겼더니 **UNF 제2조 전체(5,122자)가
「제2조제1호」 하나로 뭉쳤다.** ASCII 단어 문자만 배제하고, 오탐(「[별표 2] Ⅰ. 1. 가.」 같은 인용)은
**순번 검사**(1부터 순서대로 오르는 마커만 인정)로 걸렀다. 결과: 제2조가 호 1~6 으로 갈렸다.

### 2. 장(Ⅰ·Ⅱ·Ⅲ) 경계를 먼저 끊어야 한다

「식품등의 표시기준」은 본문 전체가 **문자열 하나**로 온다(53,216자). 장 경계를 끊지 않으면
총칙의 마지막 호 안으로 Ⅱ·Ⅲ 장이 통째로 딸려 들어가고, 공통표시기준·개별표시사항 청크의
인용 위치가 전부 「Ⅰ. 총 칙」으로 찍힌다. 이 제품에서 위치 표기는 장식이 아니라 사용자가
원문에서 그 자리를 찾아가는 경로이므로(PRD 2절) 틀린 위치는 결함이다.

로마숫자는 본문 안에서 **참조로도** 쓰인다 — 「…표시방법은 Ⅱ. 공통표시기준에 따른다」가 44곳.
장 제목만 고르는 단서 둘을 같이 썼다: (1) 제목 뒤에 바로 첫 항목 `1.` 이 붙는다,
(2) Ⅰ→Ⅱ→Ⅲ 순서로 오른다. 같은 이유로 위치 표기를 읽을 때도 로마숫자는 **청크 맨 앞에 있을 때만**
장으로 인정한다.

결과: 「본문」으로 남은 청크 0건(고치기 전 31~76건), 위치 표기의 모든 조각이 청크 본문에 실제로
존재함을 확인했다. 예 — `Ⅲ. 개별표시사항 및 표시기준 1. 식품 자. 음료류 2) 표시사항`.
