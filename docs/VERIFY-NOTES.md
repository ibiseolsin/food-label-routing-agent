# 환각 검증 규칙 — 무엇을 잡고 무엇을 못 잡나

슬라이스 6 (2026-09-17). 구현은 [`verify.py`](../verify.py), 설계 결정은 PLAN D4·D11.

검증기는 답변에서 **수치 · 조문 번호 · 식품유형명**을 뽑아 주입된 근거에 그 표기가 실제로
있는지 문자열로 대조한다. LLM 판정기를 쓰지 않는다 — 같은 입력에 다른 답이 나오면
S3(「근거 밖 진술 0건」)를 잴 수 없다.

## 실측 (2026-09-17)

| 확인 | 명령 | 결과 |
|---|---|---|
| 규칙 자체 | `uv run python verify.py --selftest` | 6건 전부 의도대로 (잡아야 할 4 · 통과해야 할 2), 종료 코드 0 |
| 슬라이스 5 기록 재대조 | `uv run python verify.py --replay data/runs/slice5.json` | 18문항 · 26건 대조 · 위반 0 |
| 슬라이스 6 관통 | `uv run python -m agent --goldenset --out data/runs/slice6.json` | 18문항 · 23건 대조 · **위반 0 · 재생성 0 · 오탐 0** |

재생성 경로는 실제 관통에서 한 번도 걸리지 않아 **답변을 일부러 틀리게 만들어** 확인했다
(존재하지 않는 `제37조제2항` · `88%`). 1차 검증이 둘 다 잡고, 위반 목록이 프롬프트로 들어가고,
2차 답변이 통과했다. 전후 답변은 기록의 `answerHistory` 에 둘 다 남는다.

### 대조 건수는 문항마다 크게 다르다

18문항에서 대조된 토큰은 23개고, **8문항은 대조할 것이 하나도 없었다**(`AD-1`·`AD-2`·`AD-3`·
`AC-1`·`AC-2`·`AC-4`·`MX-1`·`LB-3`). 답변에 숫자도 조문 번호도 식품유형명도 안 나왔기 때문이다.
「위반 0건」이 「그 답변이 근거 안에 있다」는 뜻은 아니다 — **검증기가 덮는 것은 답변의 일부**이고,
나머지(사실의 누락·왜곡)는 S2 채점기(슬라이스 8)가 본다.

## 규칙이 못 잡는 것 — 두 가지

고치지 않고 적어 둔다. 둘 다 PLAN D11 이 정한 규칙 그대로의 결과다.

### 1. 근거가 넓으면 엉뚱한 자리의 숫자에 걸려 통과한다

D11 은 대조를 「주입된 근거 **전체**」에 걸라고 정했다 — 답변이 두 청크를 합쳐 한 문장을 쓰는 것이
정상이라서다. 대신 근거가 두 도구분(약 16,000자)이면 숫자 하나가 **무관한 조문에서** 발견된다.

실측: 「과·채주스는 과·채즙 **90%** 이상이어야 한다」(실제 기준은 95%)를 `lookup_food_type` +
`lookup_labeling` 근거에 걸면 **통과한다.** 표시기준의 「카페인 함량을 90% 이상 제거한 제품은
탈카페인으로 표시할 수 있다」가 `90%` 를 갖고 있기 때문이다. 도구 하나(`lookup_food_type`)만
주입하면 같은 답변이 잡힌다.

즉 **라우터가 도구를 더 고를수록 수치 검증이 느슨해진다.** 슬라이스 9의 `라우팅 과선택` 분류가
S1 뿐 아니라 S3 에도 영향을 준다는 뜻이다.

### 2. 실재하지 않는 식품유형명은 아예 뽑히지 않는다

유형명 추출은 식품공전 음료류 유형의 **고정 사전**(`verify.FOOD_TYPES`)으로 한다. 사전에 없는 말은
추출되지 않으므로, 모델이 「유자주스는 **과즙음료**에 해당한다」처럼 **없는 유형명을 지어내면**
유형 규칙은 침묵한다. 사전을 코퍼스에서 읽지 않고 박아 둔 이유는 근거가 바뀌어도 기준이
흔들리면 안 되기 때문이고, 그 대가가 이것이다.

자체 확인의 「근거에 없는 식품유형명」 항목이 재는 것은 **실재하는 유형명을 근거 없이 끌어다 쓴
경우**다 (첨가물 근거만 주고 「과·채주스로 분류된다」고 쓴 답변). 이쪽은 잡는다.

| 질문에 이미 있던 토큰 | 「유자즙 28%」를 되풀이한 것은 지어낸 것이 아니다. 사용자가 말한 배합 비율이 법령 본문에 있을 리 없다 |

## 단위 표기 흔들림

공전은 `㎎`·`㎖`(합자)를, 답변은 `mg`·`mL` 을 쓴다. 같은 값이 다른 글자가 되면 **있는 근거를
없다고 잡는다.** 그래서 `verify.canon` 이 `tools.norm`(부호·공백 제거) 위에 단위 별칭
(`퍼센트`→`%`, `㎎`→`mg`, `포인트`→`pt` 등)을 양쪽에 똑같이 건다.

`14포인트`·`22포인트`·`7포인트`(LB-2)가 실제로 이 정규화로 통과했다.
