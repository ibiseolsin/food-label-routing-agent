## 2. 축 가드 — 두 축을 바꾸면 거부한다 (완료 기준 b)

`evaluate.py --against <직전 기록>` 이 `RunConfig` 를 대조하고, **두 축 이상 다르면 종료 코드 2로
파이프라인을 돌리기 전에 멈춘다.** 거부할 실행에 18문항치 LLM 호출을 태울 이유가 없다.

눈으로 확인한 것 — 1회차 프롬프트에 `router_prompt` 를 한 줄 더 건드리고 돌렸다:

```
축 가드 — 직전 기록 baseline-3.json
  바뀜 router_prompt d07e8b28 → d2f5aada
  바뀜 answer_prompt 6bcb1d57 → 372cfe61
    =  topic_index   a7cd423f
    =  model         gpt-4o-mini

거부 (종료 코드 2) — 한 회차에 2축이 바뀌었다: router_prompt, answer_prompt
  한 번에 한 축만 바꾼다 (PLAN D13). 되돌리고 하나씩 재라.
종료 코드 = 2
```

`--out` 으로 준 기록 파일은 **만들어지지 않았다.** 가드가 채점 전에 끊는다.

## 3. 완료 기준 (c) 는 못 넘겼다 — S2 0.67

기준선 0.61·0.56·0.67 → 1회차 0.67·0.67. **평균은 올랐지만 기준선의 폭(0.56~0.67) 안이다.**
개선 3회로 S2 를 0.75 위로 올리지 못했다.

### 3-1. 그래도 답변은 고쳐졌다 — 두 문항이 채점에 안 잡힌다

10회 실행 전체의 S2 문항별 결과를 보면 **LB-1 은 10회 모두 0점**인데, 0점인 이유가 1회차를
기점으로 **바뀌었다**.

| | 기준선 | 1회차 이후 |
|---|---|---|
| 답변 | 「…원재료명, 영양성분, 주의사항 **등이다**」 — 용기포장 재질·품목보고번호가 **없다** | 1)~14) 를 **전부** 적는다. 필수 사실의 조각이 10/10 답변에 있다 |
| 채점 | 인용이 답변에 붙고, 채점기가 「없다」고 판정 — **진짜 0점** | 채점기 인용이 「6) 원재료명 … 9) 품목보고번호, **12)** 주의사항」으로 **10)·11) 을 건너뛰어** 베낀다. `quote_grounded` 는 이어진 부분 문자열만 보므로 떨어진다 |

MX-2 도 같은 계열이다 — 채점기 인용이 답변 문장과 글자까지 같은데 **마침표 하나**가 더 붙어
있어 떨어졌다(`norm` 은 가운뎃점·괄호는 지우지만 `.` 은 남긴다).

**채점기는 고치지 않았다.** BASELINE 5절이 「회차마다 잣대가 달라지면 비교가 무의미해진다」고
못박았고, 느슨하게 고치면 슬라이스 9가 막아 둔 거짓 통과(가운데를 줄여 베낀 인용)가 되살아난다.
슬라이스 9의 AD-3 와 같은 자리다 — **계측이 답변을 못 따라오는 것을 계측 탓으로 적고 넘어간다.**

LB-1 한 문항이 0.056 이다. 이 한 건만 계측 문제로 빼도 1회차는 0.72 로 **여전히 기준 아래**다.

### 3-2. 1회차가 실제로 바꾼 것 / 깨뜨린 것

- **붙었다**: FT-3 (기준선 3회 모두 0점 → 이후 6/7 만점). 조건부 갈래를 다 적게 한 것이 먹혔다
- **붙었으나 안 잡힌다**: LB-1 (3-1)
- **깨졌다**: FT-4 (기준선 3회 모두 만점 → 1·3회차 4회 모두 0점). 「끝까지 쓴다」가 **넘겨야 하는
  문항**에서 근거를 더 적게 만들어, 넘기는 문장(별표 1 이 수집 범위 밖이라는 사실)이 밀린다.
  S4 는 아직 안 깨졌지만 2회차에서 한 번 깨진 것이 같은 자리다

**붙은 것과 깨진 것이 한 문항씩이라 총점이 안 움직였다.** 다음 회차의 후보는 여기다 —
「끝까지 쓴다」를 **답을 준 문항에만** 걸고, `no_evidence` 쪽은 지금처럼 짧게 두는 것.
