# 카테고리 매핑표

**카테고리 = 도구** 다 (PLAN 설계 결정 D1). 과제 지표가 「실제로 호출한 도구 집합이 기대
도구 집합과 정확히 일치하면 1점」이라, 도구 경계가 흐릿하면 그 지표를 잴 수 없다.

이 문서가 **어느 카테고리가 문서의 어느 부분을 보는지**의 원본이고, `tools.py` 의
`SCOPES`·`TOPICS` 가 그 구현이다. 둘이 어긋나지 않게 `uv run python tools.py` 가
이 문서에 빠진 항목이 있으면 종료 코드 1 을 낸다.

수집한 자료와 그 시행일은 [COLLECT-NOTES.md](COLLECT-NOTES.md) 와 `README.md` 에 있다.

## 2. 제2. 식품일반 공통기준을 어디에 붙였나

PLAN D8 이 정한 것을 그대로 구현했다. 제2 는 4항목 96청크(약 36,000자)를 다 받아 뒀지만
도구 1회 반환이 8,000자 이하여야 해서 전부는 못 넣는다.

| 제2 항목 | 붙인 도구 | 왜 |
|---|---|---|
| 제2. 1. 식품원료 기준 | `lookup_food_type` | 「유자 발효추출물을 원료로 쓸 수 있나」가 여기서 갈린다. 도구는 잡히되 답이 없는 자리 = UC-6 |
| 제2. 2. 제조·가공기준 | `lookup_food_type` | 「'제5. 식품별 기준 및 규격'에서 원료배합시의 기준」이 여기 있다 — **「유자즙 28%」를 어떻게 세는지**가 UC-1 의 답을 좌우한다 |
| 제2. 3. 의 **3) 식품첨가물** 한 항목 | `lookup_additive` | 식품에 쓸 수 있는 첨가물의 범위를 식품공전 쪽에서 못박는 조항 |
| 제2. 3. 의 나머지 (위생지표균·오염물질·잔류허용기준 등) | **없음** | PRD 3절의 어느 유즈케이스도 묻지 않는다. 넣으면 무엇을 자를지를 키워드 매칭이 정하게 된다 |
| 제2. 4. 보존 및 유통기준 | **없음** | 같은 이유 |

## 4. 첨가물 별칭 색인

대표는 「비타민C」라 부르고, 공전 품목명도 「비타민C」지만, 라벨에 쓸 이름은 「Vit. C」이고
같은 성분의 염은 「L-아스코브산나트륨」이다. 셋이 한 자리를 가리켜야 UC-3 이 성립한다.

**별칭의 출처는 수집한 원문 안에만 있다.**

| 출처 | 무엇 | 예 |
|---|---|---|
| 품목 청크 머리줄 | 품목명 · 영문명 · 이명 | `비타민C (L-Ascorbic Acid 이명 : Ascorbic acid)` |
| 표시기준 별표 5·6 의 「간략명」 칸 | 라벨에 쓸 수 있는 줄임 이름 | `L-아스코브산나트륨` → `아스코브산Na`, `비타민C-Na` |

2026-09-17 기준 품목 849행(중복 포함, 이름 기준 716종), 그중 별칭이 붙은 것 810행.

### 표기 흔들림 보정

이것만이 원문 밖에서 더한 것이고, **없는 품목을 만들어 내지 않는** 철자 차이 보정이다.

| 질의 표기 | 공전 표기 | 왜 |
|---|---|---|
| 아스코르브 · 아스콜빈 | 아스코브 | 공전은 「L-아스코브산」으로 쓴다 |
| 비타민씨 | 비타민C | |
| 구연산나트륨 | 구연산삼나트륨 | 별표 6 간략명이 「구연산Na」인 품목 |

### 맞추는 방향

- **앞 방향** — 품목명이 질의 안에 들어 있다. 「비타민C를 …」 → `비타민C`. 정확한 지목이라 점수가 높다
- **뒷 방향** — 질의어가 품목명 안에 들어 있다. 「아스코르브산」 → `L-아스코브산나트륨`·`L-아스코브산칼슘`

품목이 잡히면 (1) 그 품목 청크, (2) 그 품목이 실린 별표 4·5·6 조각, (3) 품목표가
「II. 2. 1)의 규정에 따라」로 넘기면 그 일반사용기준까지 함께 붙인다. 이 넘김이 굉장히
흔해서 — 비타민C·구연산 둘 다 그렇다 — 안 붙이면 답이 「따라 사용하여야 한다」에서 끝난다.

## 5. 의도된 겹침과 복수 카테고리

**표시기준 별표 4·5·6 은 `lookup_labeling` 과 `lookup_additive` 양쪽 범위에 있다.**
「이 첨가물 라벨에 뭐라 적나」는 첨가물 질문이고, 「라벨에 뭐가 들어가야 하나」는 표시 질문인데
근거가 같은 표다. 도구를 쪼개는 대신 겹치게 두고, **기대 도구는 집합으로 채점한다**(PLAN D2).

| 질문 모양 | 기대 도구 집합 |
|---|---|
| 「유자즙 28% 음료를 '유자주스'로 팔아도 되나요」 | `{lookup_food_type, lookup_labeling}` — 유형 정의 + 제품명 표시 규칙 |
| 「이 첨가물 써도 되고 라벨엔 뭐라 적나요」 | `{lookup_additive}` — 별표가 이 도구 범위에 있다 |
| 「'면역력에 좋은'이라고 써도 되나요」 | `{lookup_ad_claims}` |
| HACCP·수입신고·처분 수위 (UC-5 `out_of_scope`) | `{}` — **공집합.** 판정 노드에서 걸러 근거를 조회하지 않는다 (PLAN D3) |
| 「유자 발효추출물을 식품원료로 쓸 수 있나요」 (UC-6 `no_evidence`) | `{lookup_food_type}` — 도구는 잡히고 발췌 범위에 답이 없다 |

마지막 두 줄이 PLAN D3 의 두 갈래다. `out_of_scope` 는 **기대 도구가 공집합**, `no_evidence`
는 **해당 도구 1개**. 한 노드에서 처리하면 이 구분이 사라져 S1 을 잴 수 없다.

## 7. 검색 방식을 이렇게 정한 이유

D1 은 **벡터 검색을 쓰지 않는다**고 못박았다. 세 겹으로 대신한다.

1. **주제 색인** — 사용자의 말과 법령의 말이 다른 자리를 잇는다 (「면역력」)
2. **키워드 점수** — 질의어가 실제로 든 청크로 남은 자리를 채운다. 흔한 말이 순위를
   뒤집지 않게 문서빈도로 누른다
3. **별칭 색인** — 첨가물 품목명·영문명·이명·간략명

세 방식 다 결정적이다. 같은 질의는 늘 같은 근거를 돌려준다 — 채점기가 흔들리면 개선 축을
하나씩 바꾼 효과를 잴 수 없다 (PRD S6).

**부족하면 BM25 를 개선 축 하나로 추가한다** (PLAN D1, 슬라이스 9의 후보). 처음부터 넣지 않는다.

### 구현하며 알게 된 것 둘

- **두 자리 이하의 순수 숫자는 질의어에서 버린다.** 법령 본문에서 그런 숫자는 거의 항상
  항·호 번호다 — 「유자즙 28%」의 `28` 이 제조·가공기준 「28) 냉동수산물을 물에 담가
  해동하는 경우…」를 끌어왔다. 사용자가 말한 배합 비율은 애초에 법령 본문에 있을 수가 없다.
- **섹션은 위치 표기뿐 아니라 본문 첫머리로도 맞춘다.** 위치 표기는 단정할 수 없으면
  조상을 접는 규칙이라(`chunking.section_path`), 음료류 「거) 기타표시사항」 청크의 위치가
  「Ⅲ. 개별표시사항 및 표시기준 1. 식품」까지만 남아 있었다. 첫머리를 같이 보면 절이 통째로
  잡힌다 — 가열하지 않은 과·채음료의 의무 표시가 이 청크에 있다.
